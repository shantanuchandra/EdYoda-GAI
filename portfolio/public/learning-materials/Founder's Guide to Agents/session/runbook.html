Keep the room building.

A high-signal operating layer for a four-hour founder session: say less, observe more, protect the two real done states.

Pre-session checklist

Day-before readiness

Do not begin the live workshop with untested auth. A working fallback is more valuable than an impressive explanation.
10:00–10:35
35

Opening

Name the bottleneck. Teach the test.

Say

“Today is about the work around your product—the recurring operations work that consumes founder attention.”

Do

  • 10-minute round robin: domain + repeated task.
  • Draw the frequency × judgement matrix.
  • Land the live data + action + trigger test.

Watch

Do not let the opener become startup pitches. Pull answers back to one task with a visible recurrence.

“If it only gives you text after you ask, it is useful—but it is still a prompt. Today we will add live data, an action, and a path to running again.”
10:35–11:35
60

Build block A

Weekly Repo/Product Digest

Say

“We are building a weekly shipping translation layer, not a git-log reader.”

Do

  • Have founders validate real commit data first.
  • Ask them to adapt the plain-English digest prompt.
  • Pair founders whose repositories are quiet with the fallback repo.

Watch

Generic summaries, missing permissions, and founders skipping the live-data validation step.

“Before we ask for prose, prove the agent can see real data. A polished answer to an empty source is not a working agent.”
11:35–11:50
15

Break

Break is non-negotiable.

Keep the screen on the Build 01 done state. Use the time to identify anyone who needs a direct handoff or a fallback path for Block B.

11:50–1:05
75

Build block B

Investor Qualification + Outreach

Say

“The action is a draft, not a send. Human review is part of the design.”

Do

  • Test Gmail draft creation before research.
  • Collect round fields: stage, sector, geography, check size.
  • Switch cleanly to fallback investors when search is thin.

Watch

Unsourced investor claims, generic outreach, and ambiguity about whether the email has been sent.

“A Gmail draft proves the action boundary. Read it, edit it, then choose whether to send it. That is the right place for founder judgement.”
1:05–1:50
45

Generalise

Sketch the third agent.

Say

“Do not start with the model. Start with the repeated work you would gladly never do manually again.”

Do

  • Reopen the agent idea catalog.
  • Have each founder map trigger, data, reasoning, action.
  • Run short peer share-outs.

Watch

Over-automation of high-judgement work. Add a human approval point before any consequential action.

1:50–2:00
10

Close

Leave with a next run, not just notes.

“Run one agent on real work next week. The test is not whether the demo was elegant. The test is whether it earned another run.”

Ask each founder to name the agent they will keep alive, the first thing they will check, and the next bottleneck they would point this pattern at.

Contingency guide

Say the failure, use the fallback, keep teaching.

If a demo fails live
Name it plainly. Switch to your prepared working instance or a recorded real output. Keep the pattern visible: trigger → live data → reasoning → action.
If a repo has no recent commits
Use the shared fallback demo repo. This is a pattern rehearsal, not a scorecard for the founder’s shipping cadence.
If live investor research is thin or wrong
Switch immediately to the curated fallback list. Continue scoring and drafting; do not spend the block retrying vague searches.
If fewer than 70% finish Build 01
Do not add scheduling. Get one digest from real or fallback commit data, then move to the break on time.
If fewer than 70% finish Build 02
Protect the Gmail-draft test and one draft. Defer extra match scoring and polish.
If the room runs over
Cut catalogue browsing first, not the agent-vs-prompt distinction or the human-review boundary.
If someone says this feels brittle
Agree with the risk. Explain that the workshop is designed around small, inspectable steps and human review—not unattended autonomy.
