Use this while you build

Two agents. Real inputs. Real outcomes.

Follow the steps in order. Do not jump to the final prompt until the data and permission checks directly above it are working.

01 / Decide

The agent test

Know what you are building.

A prompt can be useful. An agent becomes useful on its own terms when it gets fresh information, changes something outside the chat, and can run again without you recreating the request.

Live dataIt pulls a repository, web result, inbox, or other system you did not paste in.
External actionIt writes, updates, drafts, or notifies somewhere beyond the chat.
TriggerIt can run from a schedule, webhook, or event—not only from a fresh manual prompt.
02 / Build

Build 01 · Weekly Repo/Product Digest

Translate shipped work into a readable update.

Your done state: Hermes has read real recent repository activity and created a short, ordinary-language summary that a non-technical co-founder can use.

Before you begin

Choose one repository with commits from the last seven days. If your repo is quiet, use the facilitator’s fallback repo; this is a rehearsal of the pattern, not a score of your velocity.

01

Create least-privilege access

In GitHub, create a fine-grained personal access token limited to the repository you selected. Grant read-only Contents and Metadata. Save it in ~/.hermes/.env as GITHUB_TOKEN, then restart Hermes if it is already open.

Do not paste the token into a chat. The only place it belongs is your local Hermes environment file.
02

Check that the repository is reachable

Ask for raw recent activity first. A generic answer is not success—look for real commit messages, dates, or changed files.

Look at the last 7 days of commits on <github-owner/repository>. Return the commit date, commit message, and a short description of the files or area changed for each item.
03

Turn the activity into a product digest

Only after Step 2 works, send the transformation prompt. If it reads like a changelog, change the audience and ask for a rewrite.

Using only the repository activity you just retrieved, write a 3–5 sentence weekly product digest for a non-technical co-founder. Group related commits into one story. Explain what changed and why it matters when the evidence supports it. No git jargon, no invented outcomes.
Rewrite the digest for <investors / customers / internal team>. Keep it under <number> words. Remove implementation detail and retain only evidence-supported product impact.
04

Make the delivery repeatable (stretch)

Once the manual run works, ask Hermes how its current scheduler is configured and create a weekly Monday 9am job. Verify the schedule in Hermes before relying on it.

Show me the supported way to schedule a weekly task in this Hermes installation. If scheduling is available, create a Monday 9am task that reads the previous 7 days of commits for <repo>, writes the approved digest format, and delivers it here. Confirm the schedule after creating it.
03 / Build

Build 02 · Investor Qualification + Outreach

Research fit, then create drafts for review.

Your done state: at least one evidence-backed fit score and one personalised unsent Gmail draft. The founder remains the decision-maker.

01

Prove the action boundary with a test draft

Connect Gmail using the Hermes-supported path. First run an explicitly safe test. Then open Gmail and confirm that the message appears in Drafts, not Sent.

Create a Gmail draft addressed to me. Subject: Hermes test. Body: This is a test draft. Do not send it.
02

Give the agent enough context to evaluate fit

Write the round facts before asking it to search. Specific context makes the source check meaningful.

I am raising a <stage> round in <sector>. I am based in <geography> and looking for approximately <check size> checks. Context that matters: <traction, business model, thesis, or restrictions>.
03

Search for candidates and inspect sources

Ask for source links, current evidence, and uncertainty. If the sources are generic or stale, stop and use the fallback list below instead of retrying a vague search.

Search for 5–8 currently active investors that could fit my round. For each, give: investor or fund name, a source link, evidence of stage/sector/geography/check-size fit, and what is uncertain. Do not include a candidate without a source.
04

Score the evidence

Score each candidate 1–3 for fit using stage, sector, geography, and check size. Give one evidence-based sentence for each score. Separate facts from inferences.
05

Create a draft, not an automated send

For <investor/fund>, draft a personalised outreach email under 150 words. Refer to one specific, sourced reason they fit my round. Create it as a Gmail draft only. Do not send it. Tell me what I should verify before sending.
04 / Reuse

Prompt templates

Copy, replace the brackets, and run.

These templates keep the safe parts of the workflow intact: evidence before claims, draft before send, and a clear boundary between fact and inference.

I want to automate this recurring founder-ops task: <task>. Design a small first version with: trigger, live data source, reasoning step, external action, human approval point, required permissions, and one read-only test. Do not assume it should auto-send, auto-delete, or make irreversible changes.
This agent step failed: <error or symptom>. Diagnose in this order: trigger, live-data access, permissions, provider/model connection, then action boundary. Give one read-only check at a time. Do not change credentials or disable security checks.
Live search was thin. Use the fallback investor rows below as my input data. Score them against my round facts. Do not claim any detail that is not in the supplied rows or a cited current source.

06 / Recover

Recovery guide

Find the broken boundary.

Hermes is not responding
Confirm the gateway is still running and check hermes status for the selected provider and model.
The repo response is generic
Return to Digest Step 2. Check the repository name, token scope, and whether the response contains real commit data before asking for a summary.
Gmail did not create a draft
Stop before research. Recheck Gmail permissions and repeat the test-draft prompt. Do not assume a successful response means the external action occurred.
SSL certificate verification fails
Do not disable certificate verification. This commonly points to a managed network inspecting HTTPS; use an unrestricted network or follow your organisation’s approved CA-certificate process.
