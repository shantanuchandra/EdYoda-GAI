# Instructor Delivery Playbook

## Purpose

This playbook is for the instructor, TA, or program operator running Production AI PM.

It explains how to deliver the cohort, manage critique, run the synced decks, keep learners on track, and protect the premium experience.

---

## Delivery Principles

- Treat learners as senior operators, not beginners.
- Spend more time on judgment than definitions.
- Use tools as evidence of product thinking, not as the headline.
- Make tradeoffs explicit.
- Critique artifacts, not personalities.
- Keep the weekly artifact tied to the final portfolio.
- Protect the 120-minute session shape.
- Never let a tool demo replace evals, risk, cost, or launch readiness.

---

## Standard 120-Minute Session Shape

| Time | Segment | Instructor job |
|---|---|---|
| 0:00-0:10 | Opening and context | Re-anchor the artifact and one rule |
| 0:10-0:35 | Strategy lens | Teach the core judgment model |
| 0:35-0:55 | Applied walkthrough | Show the model on the shared case |
| 0:55-1:05 | Break | Protect the break |
| 1:05-1:30 | Studio | Learners apply the model to capstones |
| 1:30-1:45 | Critique | Pressure-test 2 to 3 artifacts |
| 1:45-1:55 | Artifact close | Explain the assignment and quality bar |
| 1:55-2:00 | Close | Capture next action and preview next week |

If running late, shorten lecture. Do not cut critique, break, or artifact close.

## Pre-Session Checklist

Complete this 24 hours before each session.

- [ ] Review the facilitator script.
- [ ] Open the presenter deck.
- [ ] Open the learner deck once to confirm it loads.
- [ ] Open the learner workbook.
- [ ] Open the portfolio packet template.
- [ ] Prepare the shared case example.
- [ ] Prepare one strong and one weak example artifact.
- [ ] Review submissions due for critique.
- [ ] Choose 2 to 3 learner artifacts for live critique.
- [ ] Prepare the post-session message.
- [ ] Confirm recording and chat settings.

## How To Use The Synced Decks

Each week has two HTML decks:

- `W##_Presenter_Deck.html`
- `W##_Learner_Deck.html`

Use the presenter deck for facilitation notes and controls. Use the learner deck for the clean participant view.

Recommended setup:

1. Open the presenter deck.
2. Click `Learner Deck`.
3. Share the learner deck window on Zoom or Meet.
4. Keep the presenter deck visible only to the instructor.
5. Advance slides from the presenter deck.
6. Confirm the learner deck follows.

If sync fails:

- refresh the learner deck;
- move both decks back to slide 1;
- use keyboard arrows in the shared learner deck as fallback.

## Studio Facilitation Pattern

Use the same pattern every week.

1. Set the artifact decision.
2. Give 6 to 8 minutes of solo work.
3. Move to pair or small-group critique.
4. Bring back 2 to 3 examples.
5. Ask the room to identify the weakest assumption.
6. Convert critique into the take-home assignment.

Do not ask, "Any thoughts?" Ask precise critique questions:

- What is the strongest decision here?
- What is the weakest assumption?
- What would make this unsafe to launch?
- What data or context is missing?
- What should be cut from scope?

---

## Live Critique Rubric

Use this quick rubric during class.

| Dimension | What to listen for |
|---|---|
| Specificity | Named user, workflow, decision, and context |
| AI necessity | Clear reason AI is better than non-AI alternatives |
| Technical realism | System behavior, data, retrieval, tools, approvals |
| Quality bar | Concrete evals, failure modes, and launch gates |
| Production judgment | Cost, latency, privacy, safety, operations |
| Executive clarity | Can the learner explain the tradeoff in 2 minutes? |

## Handling Common Session Problems

### Learner Has A Weak Capstone

Ask:

- What workflow is actually painful?
- What decision is high-frequency or high-stakes?
- What would the non-AI version be?
- What evidence would make you kill this?

If still weak, move them to the shared Customer Success Copilot case for one week.

### Learner Wants To Build A Generic Chatbot

Redirect to workflow:

- Who uses it?
- During what task?
- What context does it need?
- What action does it support?
- What failure would damage trust?

### Learner Is Too Tool-Focused

Ask:

- What product decision does this tool output support?
- What would be true if the tool disappeared tomorrow?
- What eval would prove this is better than manual work?

### Learner Is Too Strategy-Only

Ask:

- What would the system actually do?
- What data is needed?
- What would engineering need to build first?
- What trace would you inspect?

### Learner Shares Sensitive Work Data

Pause and reset:

- ask them to anonymize;
- replace names and exact values;
- move sensitive details to a private artifact;
- remind the cohort of the confidentiality rules.

## Feedback Workflow

Use the feedback checkpoints in Weeks 2, 4, 5, 7, and 8.

Recommended feedback format:

```text
Artifact:
Current level:
Strongest signal:
Weakest assumption:
Production risk:
One improvement before next review:
```

Keep feedback short and decision-oriented. Do not rewrite the learner's work.

---

## TA Role

If using a TA, assign these responsibilities:

- monitor chat;
- collect questions in a parking lot;
- track attendance;
- note who shared artifacts;
- capture critique decisions;
- drop workbook and resource links;
- flag learners who are falling behind;
- prepare submission summaries for the instructor.

The TA should not answer strategic questions that need instructor judgment. They should triage and organize them.

---

## After-Session Checklist

Within 24 hours:

- [ ] Send recording, if applicable.
- [ ] Send learner workbook link.
- [ ] Send assignment reminder.
- [ ] Share critique notes.
- [ ] Update cohort tracker.
- [ ] Mark missing submissions.
- [ ] Add unresolved questions to the parking lot.
- [ ] Remind learners of the next artifact.

---

## Premium Experience Bar

The cohort feels premium when:

- learners know what to prepare before each session;
- live time is used for judgment and critique;
- artifacts compound into the portfolio;
- feedback is specific and fast;
- tools are practical but not gimmicky;
- the instructor can handle technical questions with clarity;
- learners leave each week with a decision, not just notes.

That is the delivery standard.
